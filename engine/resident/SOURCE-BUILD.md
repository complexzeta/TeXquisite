# Resident compiler source

Version 0.98 adds `persistentLectureFlowConfigure` for Lecture-only visual blocks. Its native whitelist admits mark nodes, deferred-write whatsits and PDF destination whatsits in addition to the existing flow nodes. Only deferred writes are removed recursively from the final copied visual list, so provisional painting never runs auxiliary/bookmark writes outside LaTeX's output-routine context. Counters and other TeX processing still execute normally. Other whatsits, inserts and unsafe boundaries retain page/full-build fallback. Ordinary flow and full-document output keep their previous rules. No TeX format or node-layout changes are introduced.

The patch/build scripts accept `PERSISTENT_TEX_ENGINE_SOURCE_ROOT` for an external engine working directory. The patcher can read its pristine Git baseline from `PERSISTENT_TEX_ENGINE_BASELINE`; the builder can read an existing SDK from `PERSISTENT_TEX_ENGINE_SDK`. Use an external `EM_CACHE`, TEMP and TMP to keep generated files off the system drive. `PERSISTENT_TEX_ENGINE_JOBS` defaults to one and accepts one through three; a single job is recommended while using the computer for other work.

`upstream-source.zip` contains the corresponding original SwiftLaTeX repository at the commit in `format.json`, including source copyright/license notices. Checkpoint changes are reproduced by `scripts/patch-checkpoint-engine.mjs`; `scripts/build-checkpoint-engine.mjs` contains compile/link flags and exports. Application/worker TypeScript, modifications and build scripts are included in the tagged GitHub source release at https://github.com/complexzeta/TeXquisite.

To reproduce the engine in the development tree, extract this archive into `.research/swift-source`, initialize a local Git repository and commit the pristine files as the baseline (the patch script reads the original files with `git show HEAD`). Install the official Emscripten SDK 3.1.46 under `.research/emsdk`. Create its `checkpoint.emscripten` configuration with `LLVM_ROOT` pointing to `upstream/bin`, `BINARYEN_ROOT` to `upstream`, and `NODE_JS` to Node.js. Set PYTHON to an installed Python executable if python is not on PATH. Run the patch and build scripts in that order. The compiler reuses the upstream WASM xpdf archive and builds the patched pdfTeX objects.

The format is engine-specific. This copy was generated with `compileFormat` from the engine and installed TeX Live 2025 resources, using the same read-only local resource mapping as the worker. `format.json` records the kernel/configuration fingerprints; the worker verifies them before loading the format. `scripts/vendor-resident.mjs` copies the rebuilt engine and records those fingerprints. A changed native kernel requires regenerating the matching format; do not bypass a mismatch check.

The worker never downloads TeX resources. Its upstream resource-request mechanism reads indexed TeX assets plus project snapshots and explicitly selected local support folders. Relative resource paths are bounded to those folders; changed dynamic dependencies invalidate cached state. TeX documents are written only into the worker's in-memory filesystem. A begin-document hook identifies the preamble checkpoint without a class/package whitelist or JavaScript parsing of the preamble. Native fallback compilation uses the application's separate source mirror and disabled shell escape.

Version 0.6 adds application-owned line provenance without changing TeX node layouts or the format ABI. `scripts/navigation-engine.c`, applied by the checkpoint patch script, tags allocated/copied character and layout nodes, then records glyph bounds during actual page output. Sparse 256-node ranges allocate metadata only where needed. The arrays, output FILE state and JSON-lines prefix participate in normal compiler checkpoint restoration. The worker recreates the reserved `.persistent-tex` directory on restore and excludes its navigation output from auxiliary convergence. The resident output is a private navigation sidecar, not SyncTeX; native compilation continues to use standard SyncTeX.


The 0.9 patch adds `_persistentEnableCharacters` and a sparse source-byte-column field. Literal horizontal-mode characters are tagged at the two character-node allocation sites, including TeX's single backed-up paragraph-opening token when it matches the underlying input buffer. Generic allocations, expansions and math do not receive inferred columns. Optional JSONL glyph records carry source file, line, zero-based byte column, page, PDF-point bounds and character code; ordinary seven-field line records remain compatible. This changes neither TeX node layouts nor the format ABI. Character output is disabled for ordinary navigation-only builds. Pixel parity with character output on/off is covered by tests, and the UI separately checks character boxes in the actual PDF before allowing edits.


The 0.10 patch extends sparse provenance to four integers per node (file, line, source-byte column, source-byte length), preserving literal argument tokens, contiguous ligature components, reconstructed hyphenation words, and exact UTF-8 expansion intervals. The patch now also changes `tex/pdftexini.c` for word collection. Token backup/argument collection and inline free-list reuse are handled explicitly; macro replacement text does not acquire guessed columns. Accent provenance is captured before lookahead can finish the Unicode expansion. Optional glyph records append a positive byte length; the reader accepts both the earlier nine-field and newer ten-field form. Actual PDFium Unicode/geometry validation remains required. There is no TeX node layout or format ABI change.


Version 0.10.1 allocates token provenance only for valid body input origins. Unmapped/preamble tokens clear existing entries without allocating sparse ranges; reused node entries are cleared before the body-ready check. Preamble token-list reads do not propagate body provenance. These changes avoid unnecessary checkpoint memory growth.

Version 0.11 emits separate mathGlyph records for optional inline math editing. Internal negative source lengths distinguish math command provenance from UTF-8 prose; exported lengths are positive. Noad fields are cleared on reuse, populated only from proven body tokens, and propagated through cleanbox, math-list conversion, math ligatures and one-noad group collapse. The patch script is the reproducible source for these hooks. Mapping-on/off PDF pixel parity covers scripts, fraction commands, roots and warm checkpoint reuse. No node-layout, format or export ABI changes are required.

Version 0.12 additionally preserves collected math argument tokens through scantoks/thetoks for amsmath align. The new scan hook accepts existing token-list origins only, with character editing enabled and the body ready, and marks copied intervals math-only. Horizontal prose refuses these math-only origins, preserving generated-text refusal. Direct control-sequence intervals are captured in body collection mode as well as math mode; noad conversion still requires actual math mode. Tests cover aligned Greek/fraction atoms, warm edits, mapping-on/off pixel parity, and unchanged Unicode/prose/ligature origins. The header declaration and hook sites are reproduced by patch-checkpoint-engine.mjs.


Version 0.33 adds `scripts/prefix-engine.c`, included by the reproducible patch script, and exports configure/reload/previous-boundary entry points. Root line reads record the physical file offset and original endline character. Native safe-boundary checks plus an exact host input-buffer comparison gate optional kind-4 checkpoints. Reload uses native inputln and falls back on incompatible trimmed input. Format and node layouts remain unchanged. Build defaults to -O3. Optional `PERSISTENT_TEX_ENGINE_LTO=1` uses a separate object directory; it was benchmarked and not selected for this release. Header/flag fingerprints invalidate cached objects, and the signature is committed only after successful linking.


Version 0.34 includes scripts/font-body-engine.c in writet1.c and adds persistent_fb_write in utils.c. Font encoding and encrypted-body callbacks are optional and enabled only during provisional flow. Source patching is checked for idempotence. The format ABI remains unchanged.


Version 0.35 adds scripts/font-memory-engine.c and scripts/font-program-engine.c. The patch replaces the four font-memory capacity checks with geometric reservation, keeps the old eight-million-cell limit, and optionally replays complete subset programs with fresh native tag registration. Format/node layouts remain unchanged. Generated patch idempotence is checked over nine files.

Version 0.66 adds persistentPageCheckpoint to temporarily disable/re-enable a local page fence at safe root-input boundaries for an unsealed execution snapshot. The worker proves actual consumed source bytes and preserves complete navigation and original source. It never captures synthetic final-page completion. Full execution restores that state with the fence disabled and still performs ordinary completion/auxiliary convergence. No format or TeX node-layout changes are introduced. scripts/page-engine.c and the build export list reproduce the addition.


Version0.70 adds opt-in arguments2(disable fence) and3(reenable) to persistentPageCheckpoint for local picture-prefix capture at ordinary horizontal input boundaries. Existing0/1full-continuation behavior remains vertical-only. Both require an actual suspended root-input checkpoint, no active scanner/output routine and an open non-EOF input. The new mode admits only the same horizontal mode already accepted by persistent_tex_should_boundary. No persistent native variables, format structures or node layouts changed, so the existing matching format remains valid. Worker source records the one-entry local-only cache, consumed-prefix/context/dependency guards, successful-render commit and memory limits.


Version 0.73 adds caller guards around the three Unicode-context lookups in navigation-engine.c. The original context function returns false when both the saved UTF-8 origin and live frame count are zero; callers now bypass that function in exactly that state. Active frames/origins use the original implementation. No persistent variables, format/node layouts, exported functions or arithmetic rules change. The ordinary non-profiled O3 build remains selected.


Version 0.74 raises persistentMathGuardVersion to 5. scripts/tikz-math-engine.c adds guarded sine/cosine helper IDs, a mode argument on the internal JavaScript plan callback, bounded recording-key instructions and validated signed replay literals. It still executes PGF operations in parser order. Recorded results enter a host cache only after successful collection; no floating-point evaluator or approximation replaces PGF. A literal-only replay uses the ordinary native-value path. Two helper control-sequence IDs are part of the normal Wasm heap snapshot; TeX format/node layouts and exported entry points remain unchanged. The non-profiled O3 build remains selected.


Version 0.85 adds optional local format preparation in Build settings for indexed TeX Live installations. Run the ordinary application build before optional engine vendoring: vendor-resident.mjs shares dist/format-fingerprint.js with the checker. Built-in format comparisons normalize only the generated first comment and CRLF in language.dat; all other bytes and core input fingerprints remain significant. Locally prepared formats additionally record exact-byte hashes of every generation dependency and verify current kpsewhich precedence, missing-resource lookups, compiler identity and the format bytes before loading. Preparation uses the bundled WASM engine, a math-document self-test, a bounded worker timeout and an app-owned cache capped at three preparations, protecting the active cache. It does not modify native installed formats. Unsupported kernels retain native compilation.
