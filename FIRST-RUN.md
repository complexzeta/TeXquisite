# Trying TeXquisite on another Windows PC

This is an early Windows x64 test release. You do not need to clone the repository, build the program, install VS Code or Node.js, or connect a GitHub account. TeXquisite runs locally.

1. Install [TeX Live](https://tug.org/texlive/windows.html), including latexmk, if you do not already have it. Your TeX installation supplies packages and fonts; TeXquisite does not install a distribution or missing packages.
2. Download **TeXquisite-0.132.0-Windows.exe** from the [0.132 release page](https://github.com/complexzeta/TeXquisite/releases/tag/v0.132.0) and put it in a folder of your choice. It is a portable application: run the executable directly. The first launch can take a while to unpack. It is an unsigned preview build, so Windows may show a publisher warning. The release page provides its SHA-256 checksum.
3. Confirm the TeX installation in Build Settings, or select its installation/executable folder. Choose **Check installation**, then **Apply**. If fast preview is unavailable for the detected TeX Live installation, try **Prepare matching fast preview**, then **Apply**; this optional setup can take a couple of minutes once.
4. Open your `.tex` file. For teaching, choose **Build → Working mode → Lecture** and **Continuous scroll**. Automatic saving and preview are on by default.

To update, close the old version normally and run the new executable. The app keeps its local session, settings and source backups separately from the executable. Keep your normal document backups as well.

On first launch, Build Settings shows the detected installation. Discovery checks PATH and common Windows TeX Live and MiKTeX locations. If your installation is elsewhere, choose its installation folder or executable folder. Check installation reports whether the selected engine, kpsewhich and latexmk run successfully, and whether article.cls, amsmath.sty, graphicx.sty and tikz.sty can be found. A failing latexmk can indicate a missing Perl runtime; its error appears in the details. Other packages and external processors depend on the document and can produce additional build errors.

Choose Apply to remember the folder. The selected folder is added to this app's child-process PATH; Windows' system PATH is not changed. Tools are checked together within the selected installation, so a missing latexmk is not silently borrowed from a different TeX distribution. A custom latexmk executable remains available for advanced native compilation.

Windows with TeX Live is the initial supported setup. MiKTeX native compilation remains experimental, with limited clean Windows Server 2022/2025 checks passing for the earlier 0.122 portable. Install Perl as well as MiKTeX so latexmk can run, and either install required packages through MiKTeX Console or explicitly enable MiKTeX automatic package installation. The fast local lecture-preview pipeline is currently available only with TeX Live. See [MiKTeX results and limits](MIKTEX-COMPATIBILITY-RESULTS.md). Version 0.124 includes the later missing-package diagnostic fix, but this release's timing validation used TeX Live.

The bundled fast-preview format must match the selected installation's LaTeX files. Settings distinguishes compatible fast preview from native compilation only. If incompatible, native compilation is still available when its tools are ready, but updates can be slower; a notice remains visible. For an indexed TeX Live installation, choose **Prepare matching fast preview** to try generating and checking a local format, then choose **Apply**. This optional one-time setup can take a couple of minutes. Successful formats are cached across restarts and checked against the compiler and their TeX inputs; changed inputs require preparing again. Some kernels may not work with the bundled pdfTeX engine, in which case native compilation remains available. Selecting XeLaTeX, LuaLaTeX, the PostScript pipeline or a custom latexmk command also uses native compilation.

The compiler no longer prefers paths from the developer's machine. Installation selection is remembered locally; source documents remain ordinary TeX files. Report your Windows version, TeX distribution/year, the Build Settings check result, and the build error or slow-edit timing when reporting a problem. No diagnostic is uploaded automatically.

Switching to a standalone .tex tab also selects that document for the preview and Build. Included chapter/support tabs retain their known parent document. Live can be paused while editing; Build still compiles the selected document.

Choose **Build → Working mode → Lecture** for interactive teaching, preferably with Continuous scroll. Successful local edits retain the interactive formatter instead of triggering an idle full-document check. Build verifies the entire document on demand; Export PDF verifies current source before exporting. Broader edits still trigger a full build when needed, so Lecture mode does not guarantee a particular latency. **Document** is the default and verifies the whole document automatically after typing pauses. Working mode is remembered across restarts; automatic saving and backups work in both modes.
